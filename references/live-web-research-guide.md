Enterprise protocol empowering the Lead Orchestrator and specialized worker subagents to proactively search the web, official SDK documentation, GitHub repositories, and developer ecosystems for cutting-edge, professional, and non-traditional software solutions.

## 2. Research Triggers & Proactive Workflows (مسارات البحث الاستباقي)

### 🔬 1. Up-to-Date API & SDK Documentation Research
- **When**: Whenever working with a framework version, new library, or unfamiliar API.
- **Workflow**: Search official docs (e.g. `Microsoft Learn C# .NET 9`, `FastAPI latest docs`, `React 19 hooks`, `Android 15 SDK`) to pull exact signatures, parameter types, and lifecycle requirements.

### 🔍 2. Obscure Error & Bug Forensics
- **When**: When encountering cryptic compiler errors, framework reflection failures, or platform-specific crashes.
- **Workflow**: Query exact error strings and stack trace signatures across GitHub issues and developer forums to discover proven, battle-tested solutions.

### 💡 3. Creative & Non-Traditional Architecture Discovery
- **When**: Designing new features or optimizing legacy bottlenecks.
- **Workflow**: Investigate modern patterns (e.g. Zero-Copy I/O, Event-Driven Actor Models, Clean Architecture, High-FPS Accessible UI Pipelines) to deliver state-of-the-art implementations.

---

## 3. Grounded Verification Rule (قاعدة التحقق والتوثيق)
- Never rely on outdated training memory for fast-evolving APIs.
- Every external solution must be cross-verified against official documentation and tested against `validate_code.py` before landing in the codebase.
