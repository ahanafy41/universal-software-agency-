منظومة برمجية مؤسسية مستقلة بنسبة 100% (**Zero External Dependencies**) ومبنية بهندسة خماسية رشيقة فائقة السرعة (**5-File Lean Architecture**). مصممة خصيصاً **لأجهزة الكمبيوتر والمشاريع البرمجية الضخمة**؛ لتمكين المبتدئين وغير المبرمجين إلى جانب كبار مهندسي البرمجيات من بناء وتطوير أنظمة عملاقة عبر:
1. **استجواب سقراطي تفصيلي مستمر في كل كبيرة وصغيرة (من التأسيس حتى التسليم)**.
2. **رأي هندسي ناقد وصريح للأخطاء المنطقية والمعمارية (Strictly No Yes-Men)**.
3. **تفويض إلزامي للوكلاء الفرعيين النشطين بسياقات معزولة (Clean Context Active Subagents)** لمنع تلوث الذاكرة وحفظ الاستقرار في المشاريع الكبيرة.
4. **قاعدة الـ 100 سطر الصارمة للملفات** لضمان نقاء المعمارية ومنع كسل أو اختصار النماذج.
5. **اختبارات المنطق والـ Assertions الميكانيكية بنسبة 100%** عبر كافة لغات البرمجة والمنصات.

> **المبدأ الفولاذي الأساسي**:  
> **مخالفة حرفية القواعد هي مخالفة لروحها؛ لا يُقبل أي التفاف أو تجاوز بدعوى السرعة أو المرونة.**  
> *(Violating the letter of the rules is violating the spirit of the rules).*

## 🌟 الركائز الأساسية للمشاريع الكبيرة والكمبيوتر

1. **الاستقلالية التامة (Zero External Dependencies)**:
   - مهارة قائمة بذاتها بالكامل؛ لا تحتاج أي مهارات إضافية، وتعمل بنظام التشغيل الفوري.
2. **الاستجواب السقراطي المستمر في كل كبيرة وصغيرة**:
   - حظر البدء في أي كود قبل استجواب تفاعلي يغطي كل التفاصيل: من التأسيس (الأهداف والفئات وقيود المنصة وإمكانية الوصول)، إلى المعمارية (حالات انقطاع الاتصال/الطاقة وتزامن البيانات)، إلى التنفيذ (حالات الحافة والمهلات)، إلى الاكتمال والتسليم.
3. **الرأي الهندسي الصريح ونقد الأخطاء المنطقية (Strictly No Yes-Men)**:
   - يُحظر على الوكيل أن يكون مجرد منفذ أعمى أو مجاملاً؛ يتدخل فوراً لإبداء رأيه الهندسي الصريح والتحذير من أي عيب منطقي، ثغرة أمنية، خطر تهنيج، أو استهلاك غير رشيد للموارد، مع تقديم الحل البديل الأمتن ومقارنة الإيجابيات والسلبيات.
4. **التفويض الإلزامي للوكلاء الفرعيين النشطين (Active Isolated Subagents)**:
   - في المشاريع الكبيرة على الكمبيوتر، المنسق العام يقود التخطيط والاستجواب فقط، ويفوض مهام البحث والتكويد والـ QA لوكلاء فرعيين نشطين في سياقات معزولة تماماً لمنع نفخ السياق وضياع الذاكرة.
5. **الأمانة التامة لغير المبرمجين**:
   - شرح القيود والبدائل بصدق وتسليم الكود بملف تشغيل فوري بنقرة واحدة (`run.sh`/`run.bat`) ينشئ البيئة الافتراضية تلقائياً ويدعم الفحص الذاتي (`--doctor`).
6. **قاعدة الـ 100 سطر الصارمة للملفات**:
   - حظر تام لأي ملف كود يتجاوز 100 سطر كود لضمان تقسيم الكود إلى وحدات معمارية صغيرة وسهلة القراءة ومريحة لقارئات الشاشة.
7. **فحص المنطق والـ Assertions الميكانيكي**:
   - حظر الاكتفاء بفحص السنتاكس؛ تشغيل حقيقي للاختبارات وتأكيد صحة المعادلات والنتائج بالأرقام والـ `assert` بنسبة 100% نجاح.
8. **بوابة التصحيح الذاتي الصامتة (3-Strike Self-Healing)**:
   - في حالة فشل أي فحص، ينفذ الوكيل ذاتياً حتى 3 محاولات صامتة لعزل السبب الجذري والإصلاح وإعادة الفحص قبل إزعاج المستخدم.
9. **استمرارية الجلسات والذاكرة الثابتة (`tasks.md`)**:
   - تتبع دقيق للمهام بمربعات `[ ]` و `[x]` ومؤشر `👉 CURRENT TASK` لضمان إكمال المشاريع الكبيرة عبر الجلسات دون فقدان للذاكرة.

## 🛡️ جدول إفحام المبررات (Rationalization Table)

| المبرر أو حيلة الالتفاف | الحقيقة الهندسية الصارمة والرد الإلزامي |
| :--- | :--- |
| *"المشروع كبير، فهعمل البحث والتكويد في نفس المحادثة أسرع"* | كارثة سياق (Context Dilution). المشاريع الكبيرة تفرض إطلاق وكلاء فرعيين نشطين بسياقات معزولة لحماية ذاكرة المنسق. |
| *"المستخدم طلب ميزة واضحة، هبدأ كود علطول من غير أسئلة"* | التخمين خيانة هندسية. استجوب المستخدم في حالات الحافة وسيناريوهات الفشل ووثق القرارات أولاً. |
| *"هنفذ التصميم زي ما المستخدم قاله حتى لو فيه عيب منطقي"* | ممنوع دور المجامل (No Yes-Men). واجبك إبداء رأيك الناقد الصريح، تحذيره من العيب المنطقي، واقتراح البديل الأمتن. |
| *"الملف 105 أسطر بس وفصله صعب"* | الفاحص الميكانيكي سيسقطه فوراً بـ `[ModularBloatViolation]`. افصل المسؤوليات فوراً؛ لا استثناء لسطر واحد. |
| *"السنتاكس سليم والـ AST مر"* | السنتاكس يمر حتى لو الدالة ترجع `None` أو معادلة خاطئة. لا اعتماد بدون `assert` حقيقي يجتاز `--run-tests`. |
| *"هسيب تعليق أو TODO والمستخدم يكمله"* | المستخدم قد يكون غير مبرمج أو كفيف؛ ترك كود ناقص جريمة هندسية. الكود يُسلَّم كاملاً 100% دون نواقص. |
| *"العطل واضح وهصلحه فوراً بدون إثبات"* | الترقيع بدون إثبات مصغر (Reproduction First) يخلق أعطالاً جانبية صامتة. اثبت العطل أولاً ثم أصلحه. |
| *"مش محتاج نسخة احتياطية"* | أي تعديل بدون `backup_manager.py backup` مخاطرة ممنوعة. النسخ يستغرق 0.1 ثانية فقط ويحمي الكود. |

## 🚩 علامات الخطر (Red Flags)

- القيام بالبحث وتعديل الملفات المتعددة داخل سياق المحادثة الرئيسي في المشاريع الكبيرة دون إطلاق وكلاء فرعيين نشطين.
- الشروع في كتابة أي كود قبل استجواب المستخدم في تفاصيل المرحلة وتوثيقها في `BRAINSTORMING.md`.
- تمرير أو تنفيذ منطق برمجي يحتوي على عيب أو ثغرة دون إبداء الرأي الهندسي الناقد وتحذير المستخدم.
- ملف يتجاوز 100 سطر كود لأي مبرر كان.
- وجود كلمة `TODO` أو `FIXME` أو أكواد مقتطعة `... rest of code`.
- الادعاء بأن "الكود يعمل" بمجرد قراءة الكود بالعين دون تشغيل `--run-tests` بنجاح 100%.
- تعديل كود لعلاج كراش دون إنشاء سكريبت مصغر يثبت الكراش مسبقاً.

## ⚡ التشغيل والاستخدام

المهارة تعمل فوراً بمجرد نسخها إلى مجلد المهارات:
- فور طلب أي مهمة برمجية، يطلق المنسق العام جلسة الاستجواب السقراطي المستمرة في كل كبيرة وصغيرة.
- يُبدي الوكيل رأيه الهندسي الصريح وينتقد أي عيب منطقي أو خطر تصميمي ويطرح البدائل الأمتن.
- في المشاريع الكبيرة، يفوض المنسق المهام الثقيلة (البحث، التكويد، الـ QA) لوكلاء فرعيين نشطين في سياقات معزولة.
- ينفذ الكود خطوة بخطوة، مع نسخ احتياطي لحظي، وبكود لا يتجاوز 100 سطر للملف.
- يتم تشغيل الفاحص الشامل:
  ```bash
  python3 scripts/validate_code.py --strict --human-grade --run-tests .
  ```
- لا يُعتمد الكود إلا بعد ظهور: `[PASS] All behavioral and assertion tests passed 100%!`.
